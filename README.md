## 어떤 곳인가요?

개발하며 겪은 일을 쓰는 기술 블로그이면서, 성격이 다른 글을 각자 맞는 자리에 두는 공간이에요.

| 글 | 무엇을 |
|---|---|
| 포스트 | 겪은 문제와 해결을 쓴 기술 글. 한국어 · 영어 |
| 시리즈 | 여러 편으로 이어지는 글 |
| 아티클 | 인상 깊게 본 유튜브 · 테크 블로그를 정리 |
| 노트 | "깔끔해야 한다" 는 강박 없이 남기는 짧은 학습 메모 |

<br>

## 왜 직접 만들게 되었나요?

> Velog → Jekyll(Chirpy) → 커스텀 블로그

처음엔 Velog 로 시작했어요. 그런데 이력서에 건 블로그 링크를 면접관이 눌렀을 때 503 이 떠 있다면...?
놀랍게도 실제로 있었던 일이에요. 기술 글로 쓰기엔 가벼운 지식을 따로 둘 곳도 없었고요.

Jekyll(Chirpy 테마)로 옮겨 1년쯤 잘 썼지만, 두 가지가 계속 걸렸어요.

- **고치기 어렵다** — 스타일이 테마 쪽에 있어서 내 저장소에는 파일이 없었어요. AI 에게 고쳐 달라고 해도 없는 파일을 짐작으로 고쳤죠.
- **관리할 곳이 없다** — frontmatter 는 에디터로 직접 고치고, 썸네일 · 번역은 GitHub Actions 로 따로 돌렸어요. 관리가 여기저기 흩어졌어요.

그래서 원하는 기능을 명세로 정리하고, 그대로 직접 만들었어요.

<br>

## 직접 만들어서 할 수 있는 것

| | 할 수 있는 것 | 예를 들면 |
|:-:|---|---|
| ✍️ | **어디서든 쓰고 고치기** | 백오피스에서 휴대폰으로도 쓰고, 자동 저장된 드래프트를 이어 써요 |
| 🔀 | **쓴 자리에서 발행까지** | 메타데이터를 고치고, 그 자리에서 커밋하거나 PR 을 만들어요 |
| 🪄 | **글 밖의 일은 덜기** | 홈서버에 연동된 Hermes 가 글 검토 · 태그와 설명 제안 · 번역을 맡아요. 썸네일은 이미지 모델로 만들고, 옵시디언에서 쓴 노트도 가져와요 |
| 🔍 | **흩어진 글을 한 번에 찾기** | 아티클 · 노트까지 통합 검색(⌘K). 카테고리 · 태그 · 연도별 타임라인 · 시리즈로도 이어 봐요 |
| ✅ | **잘못된 글은 올라가기 전에** | PR 마다 frontmatter · 코드 블록 · 이미지 경로를 검사해요 |
| 🤖 | **사람도 AI 도 읽기 쉽게** | RSS(한국어 · 영어)와 `llms.txt` 로 글을 내보내요 |

> 무엇을 만들지는 직접 명세로 정하고, 코드는 AI 와 함께 썼어요 — [블로그 마이그레이션 이야기](https://youngsu5582.today/posts/blog-migration-to-custom-blog)

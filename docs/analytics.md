# 블로그 분석 운영 메모

## 현재 측정

운영 빌드에서 Google 태그를 직접 사용한다. GA 속성 설정과 실제 배포 버전은 저장소만으로 확인할 수 없다. `page_view`는 태그 기본 설정과 GA의 향상된 측정 설정에 맡기며, 수동 SPA 이벤트를 추가하지 않았다.

**개인정보 확인 필요:** 별도의 `/search` 페이지는 검색어를 `?q=` URL에 넣는다. GA의 `page_location`이나 향상된 사이트 검색 설정을 통해 이 값이 수집될 수 있다. GA 데이터 스트림의 [데이터 삭제 설정](https://support.google.com/analytics/answer/13544947)에서 쿼리 키 `q`를 삭제 대상으로 지정하고 테스트한다. 향상된 측정의 사이트 검색 자동 수집은 별도 확인·필요시 비활성화한다. 데이터 삭제는 HTTP 헤더 등 모든 수집 경로를 보장하지 않는다. 기존 데이터 처리 방침도 확인한다. 새 이벤트가 검색어를 보내지 않는 것만으로 전체 사이트의 검색어 미수집을 보장할 수 없다.

| 이벤트 | 기준과 매개변수 |
| --- | --- |
| `search_results` | 다이얼로그에서 입력이 500ms 멈추거나 그 전에 선택할 때, 또는 검색 페이지에서 결과가 표시될 때. `result_count`는 필터 적용 및 표시 제한 전 전체 건수(0 포함), `language`는 검색 언어(검색 페이지는 `all`), `search_surface`는 `dialog`/`page`, 검색 페이지는 콘텐츠 필터 `search_filter`도 기록한다. 검색어는 이벤트에 넣지 않는다. |
| `search_result_select` | 검색 결과 선택 시 `result_type`, 1부터 시작하는 `result_rank`, `language`, `search_surface`. 선택은 목적지의 실제 열람을 보장하지 않는다. 다이얼로그의 노트는 현재 목록으로 이동한다. |
| `article_end_reached` | 포스트·아티클의 MDX 본문 바로 뒤가 화면에 보일 때, 페이지 표시마다 한 번. `content_id`, `content_type`, `language`. 짧은 글은 진입 직후 발생할 수 있고 빠른 스크롤도 포함하므로 완독이 아니다. 아티클은 스키마에 언어가 없어 `ko`로 기록한다. |
| `content_navigation_click` | 포스트 상세의 관련 글, 시리즈의 다른 글, 이전/다음 글 클릭. `source_content_id`, `destination_content_id`, `location` (`related`, `series`, `prev_next`). 시리즈 전체 목록 링크는 제외한다. |
| `share` | 포스트에서 링크 복사가 성공한 경우 `method=copy_link`. 실제 공유 완료를 뜻하지 않는다. |
| `share_click` | X·LinkedIn 공유 링크 클릭 시 `method`, 포스트 `content_id`. 실제 공유 완료는 알 수 없다. |
| `code_copy` | 포스트·아티클에서 코드 복사 성공 시 글 식별자, 콘텐츠 유형, 사용 가능한 경우 코드 언어만 기록한다. 코드 내용은 보내지 않는다. |
| `lang_change` | 전역 언어 스위치, 목록 언어 선택 또는 번역 글 링크를 통한 전환 요청 시 `from_language`, `to_language`, `location`, 포스트 상세인 경우 `content_id`. 전환 요청이며 페이지 도착을 보장하지 않는다. |

기존 외부 링크·테마 이벤트 함수는 정의만 있고 호출되지 않는다. 예전 `search`, `read_complete`는 새 이벤트와 정의가 다르므로 과거 데이터와 합산하지 않는다. 페이지 조회, 자동 외부 링크, 90% 스크롤은 GA 설정에 따라 수집될 수 있다.

## 배포 후 확인

1. GA 관리 > 데이터 스트림 > 웹 > 향상된 측정에서 페이지 로드와 브라우저 기록 변경 측정, 외부 링크, 스크롤, 사이트 검색 설정을 확인한다. 사이트 검색·URL·외부 링크 매개변수에 개인정보가 들어갈 가능성도 살핀다.
2. Tag Assistant 또는 디버그 모드를 켜고 DebugView에서 첫 진입, 내부 링크 이동, 뒤로 가기마다 `page_view`가 정확히 하나인지 확인한다. 각 이벤트의 `page_location`, `page_referrer`도 비교한다. 쿼리 문자열만 바뀌는 언어 전환도 별도로 확인한다.
3. 검색 0건, 20건 초과, 빠른 결과 선택, 한/영 전환을 시험하고 이벤트 매개변수와 검색어 미포함을 확인한다. 검색 결과 선택과 실제 목적지의 `page_view`를 구분한다.
4. 포스트·아티클에서 본문 끝 전후, 짧은 글, 빠른 스크롤, 글 간 이동 및 뒤로 가기를 시험한다. 관련 글·시리즈·이전/다음 클릭의 출발·도착 값을 확인한다.
5. 코드 복사 성공·실패, 전역/목록/본문 번역 전환, X·LinkedIn 공유 클릭과 링크 복사를 각각 확인한다. 외부 링크 자동 수집과 `share_click`은 같은 클릭의 다른 의미이므로 합산하지 않는다.
6. 보고서에 필요한 매개변수는 GA의 맞춤 정의 등록과 수집 이후 데이터 반영 여부를 확인한다. 고유 slug가 많은 차원은 카디널리티(cardinality) 및 `(other)` 영향을 살핀다.

GTM 도입 시 직접 태그와 GTM 태그, GA 자동 기록 추적과 GTM 기록 추적을 동시에 켜지 않도록 이전 계획을 세운다. 참고: [Google SPA 측정 가이드](https://developers.google.com/analytics/devguides/collection/ga4/single-page-applications), [향상된 측정](https://support.google.com/analytics/answer/9216061).

## 데이터를 이용한 개선 가설

- 검색 결과 0건 비율과 결과 선택 비율을 언어별로 본다. 원문은 없으므로 원인을 특정할 수 없고, 검색 색인·동의어 보완은 별도의 개인정보를 수집하지 않는 정성 확인이 필요하다. 빠른 선택은 결과 이벤트를 즉시 기록하지만 선택 없는 빠른 닫기는 500ms 이내면 기록되지 않는다.
- 본문 끝 도달과 참여 시간을 유입 경로·글 길이별로 함께 비교해 도입부나 구조 개선 후보를 찾는다. 조회와 도달은 같은 기간·단위로 비교하고 인과관계나 완독으로 해석하지 않는다.
- 관련 글·시리즈·이전/다음의 클릭을 위치별로 비교해 다음 글 안내를 개선한다. 노출 수가 없으므로 클릭 수만으로 클릭률을 계산하거나 위치별 효과를 단정하지 않는다.
- 검색 다이얼로그에서 노트가 목록으로만 이동하므로 이미 존재하는 개별 노트 경로로 연결하는 UX를 검토한다. 검색 선택 이후 실제 목적지 조회와 이어지는지 확인한다. 별도 `/search` 페이지는 검색 방식과 측정 범위가 다르므로 함께 검토한다.
- 코드 복사와 언어 전환은 글 개선 후보를 찾는 보조 지표로 본다. 공유 버튼 클릭은 실제 공유 완료와 구분하고, 외부 링크는 자동 측정 확인 후 중복 없이 해석한다.
